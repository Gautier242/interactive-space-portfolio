## 3. Architecture, and the one rule that matters

`js/app.js` (~3000 lines) is the original app. Everything added lives in
`demo/*.js`, loaded after it, reaching into its globals and wrapping behaviour.
Deleting a script tag reverts a feature. **Keep doing this.**

Load order in `index.html` (16 scripts):
```
cinematic → framing → moon-view → real-models → orbits → reticles → camera →
hover-info → tooltips → rover-look → rover-tour → tour3 → neural → figure →
moon-touch → mobile
```

Files added this session:

| File | Does |
|---|---|
| `demo/mobile.css`, `demo/mobile.js` | the entire mobile layout |
| `demo/moon-touch.js` | Moon-surface pinch + tolerant tap selection |
| `demo/figure.js` | opens the publication figure full size; desktop panel balance |
| `demo/_profile.js` + `profile.html` | per-frame profiler (not loaded by `index.html`) |

**Classic-script scoping:** top-level `const`/`let` in `app.js` (`PUBS`, `bodies`,
`camera`, `sun`, `moonViper`…) are NOT on `window`, but they ARE in the shared
global lexical environment, so another classic script can reference them by bare
identifier. `function` declarations (`showDetail`, `zoomToBody`, `enterRoverMode`)
DO land on `window` and can be wrapped. This is how the overlays work, and it is
also why a browser probe must inject a `<script>` rather than reach through
`iframe.contentWindow.PUBS`.

## 4. Decisions already made — do not silently reverse these

- **Mobile is a one-shot user-agent sniff** (`index.html`, top). A phone asking
  for "Desktop site" fails it and gets the desktop layout with none of the mobile
  rules. That is **intended** — it is what the visitor asked for. Anything that
  must hold for *any finger on glass* goes behind `(pointer: coarse)`, which
  survives the spoofed UA. Do not "fix" this by widening the sniff.
- **Planet textures stay at 2048×1024.** They are WebP now, half the bytes, same
  pixels. `js/planets-real.js:114-124` derives crater relief for Moon, Mercury
  and Mars from texture luminance sampled at a UV offset tuned for 2048 px.
  Halving them changes how those bodies look. This is why the obvious "2k→1k"
  saving was declined.
- **Figures are never cropped.** `object-fit: contain` everywhere. The user has
  rejected five panel designs over `cover`. This is close to a standing order.
- **The tour never auto-starts**, on any device. It runs only from "How to
  explore". On mobile that button opens a *text sheet* instead of the demo,
  because the demo drives the real controls and reads as chaos on a 40vh map.
- **Shadows are off** and were measured to cost 25 of 41 fps. Settled. Do not
  re-litigate.
- **The pause glyph is drawn in CSS**, not a character. `⏸`/`▶` are emoji and
  render from a colour font — the button came out orange and ignored `color`.
  Seven call sites across two files write it; one that forgot the variation
  selector was enough to bring the orange back. It is now an `is-play`/`is-pause`
  class. **Do not put the character back.**
- **The publication figure opens in a new tab** (`demo/figure.js`) rather than a
  lightbox. `demo/panels.js` contains an unused lightbox; `index.html` does not
  load it, and the previous panel redesigns it belongs to were all rejected.

## 6. Traps — this section will save you the most time

**Headless Chrome is the only browser available.** Both MCP browsers failed this
session (Playwright timed out; the Chrome extension was not connected). Drive
Chrome directly:

```
perl -e 'alarm shift; exec @ARGV' 110 \
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --no-sandbox --enable-unsafe-swiftshader \
  --use-gl=angle --use-angle=swiftshader --virtual-time-budget=30000 \
  --window-size=1300,950 --user-data-dir=$S/prof \
  --dump-dom http://localhost:4321/_probe.html > $S/out.html
```

`--enable-unsafe-swiftshader` is **required** — without WebGL the app renders no
publication list at all and you will misdiagnose it as a regression. Probe a
mobile viewport by loading `index.html` in a 390×844 `<iframe>`.

Serve with no-store, always:
```
/usr/bin/python3 -c "import http.server as h
class H(h.SimpleHTTPRequestHandler):
    def end_headers(self):
        self.send_header('Cache-Control','no-store'); h.SimpleHTTPRequestHandler.end_headers(self)
h.test(HandlerClass=H, port=4321, bind='0.0.0.0')"
```
Use `/usr/bin/python3` specifically: it is the binary already allowed through the
macOS firewall, which matters if the user tests from a phone over the hotspot.

**Traps that cost real time this session:**

1. **`--virtual-time-budget` freezes CSS transitions.** `getComputedStyle` keeps
   returning the transition's *start* value forever. A divider drag looked
   completely broken while the code was correct. Set
   `el.style.transition = 'none'` in the probe before measuring anything animated.
2. **rAF barely ticks under virtual time.** Flight animations and follow loops do
   not complete. Verify the *pose* the camera will settle on, not the pixels.
   A frame-counting probe never even resolved.
3. **Headless does not advance animated-image frames.** You cannot verify an
   animated WebP plays. Validate the instrument against the raw file first.
4. **The disk fills.** Each Chrome run wants its own `--user-data-dir` (reusing
   one crashes swiftshader after several runs). The user's disk hit 100% and the
   Bash tool could not even create its own output file — no commands at all,
   including git. **Delete the profile immediately after every run**
   (`rm -rf $S/prof`). Disk was at 92% / ~1.1 GB free at handover.
5. **`.click()` is not a click** — skips hit-testing. Use `elementFromPoint` and
   dispatch to whatever is actually there.
6. **A commit message with double quotes breaks `git commit -m` in this shell.**
   Write the message to a file and use `git commit -F`.
7. **The user's screenshots may not be this site.** One reference screenshot
   contained text ("FULL MAP", "Nine projects in AI for space…") that exists
   nowhere in the repo or live site. Check before chasing a phantom.
