## 3. Architecture, and the one rule that matters

`js/app.js` (~3000 lines) is the original app. Everything added lives in
`demo/*.js`, loaded after it, reaching into its globals and wrapping behaviour.
Deleting a script tag reverts a feature. **Keep doing this.**

Load order in `index.html`:
```
cinematic → framing → moon-view → real-models → orbits → reticles → camera →
hover-info → tooltips → rover-look → rover-tour → tour3 → neural → figure →
moon-touch → mobile
```

**Classic-script scoping:** top-level `const`/`let` in `app.js` (`PUBS`,
`bodies`, `camera`, `sun`, `moonViper`…) are NOT on `window`, but they ARE in
the shared global lexical environment, so another classic script can reference
them by bare identifier. `function` declarations (`showDetail`, `zoomToBody`,
`enterRoverMode`) DO land on `window` and can be wrapped.

### The overlay-wrapping trap that bit twice today

**Before declaring anything fixed in `app.js`, grep every `demo/*.js` for the
symbol.** Two bugs this session were "fixed" in `app.js` while an overlay
re-applied the old behaviour one layer up:

- `pausedPlanets = true` was removed from `showDetail` in `app.js`, but
  `camera.js`'s `zoomToBody` wrapper set it again on every call. The fix was
  reported as done and was not.
- `rover-look.js` registered a rAF callback after `app.js` on the reasoning
  that running later meant winning. `app.js` **renders inside its own
  callback** (`app.js:1928`), so a later callback writes its pose after the
  frame is already drawn. Drag-to-look had never worked, on any device, since
  it was written. It now wraps `moonRenderer.render` instead.

The general rule: **running later only wins if the render happens after you.**
To affect a frame, wrap the render call — the pattern `cinematic.js` uses.

## 4. Decisions already made — do not silently reverse these

- **Mobile is a one-shot user-agent sniff** (`index.html`, top). A phone asking
  for "Desktop site" fails it and gets the desktop layout with none of the
  mobile rules. That is **intended**. Anything that must hold for any finger on
  glass goes behind `(pointer: coarse)`, which survives the spoofed UA.
- **Figures are never cropped.** `object-fit: contain` everywhere. Five panel
  designs were rejected over `cover`. Standing order.
- **Full-width figures were tried and rejected.** They turn a list you read
  into a gallery you scroll. The thumbnail-beside-text card is the answer.
  Note the reference the user pointed at (mattfernandez.me/projects.html)
  actually uses image-on-top cards — what he wanted from it was the *navigation*.
- **There is no mode switch. The chevron has three stops.** A separate
  `Animation`/`Projects` tab pair was built and went through five visual
  iterations — underlined tabs in the list heading (missed entirely), a
  segmented control (~38px, "takes too much space"), coloured text (~21px,
  "not buttons"), browser tabs (~22px) — before the user pointed out the real
  problem: the tabs and the chevron were two controls doing one job, trading
  map for text. All of it was deleted. **Do not reintroduce a mode switch.**

  A third chevron stop had been removed by an earlier agent for making the
  control unpredictable, but that one was at the LARGE end and competed with
  full screen. This one is at the small end, where every press means "less
  map". That distinction is why it works.
- **Planet textures stay at 2048×1024.** `js/planets-real.js:114-124` derives
  crater relief from texture luminance at a UV offset tuned for 2048 px.
- **The tour never auto-starts**, on any device.
- **Shadows are off** and were measured to cost 25 of 41 fps. Settled.
- **The pause glyph is drawn in CSS**, not a character. `⏸`/`▶` are emoji and
  render from a colour font — the button came out orange and ignored `color`.
  It is an `is-play`/`is-pause` class. **Do not put the character back.**
- **The publication figure opens in a new tab** (`demo/figure.js`), not a
  lightbox. `demo/panels.js` has an unused lightbox; it is not loaded.
- **`css/main.css:167` hard-codes `.app { height: calc(100vh - 77px) }`.**
  The mobile header has never actually been 77px, and the difference showed as
  a band of body background along the bottom of the page — worse after every
  header change. The mobile layout now makes `body` a flex column that owns the
  viewport in `dvh`, with `.app` taking whatever the header leaves. Do not
  reintroduce a magic number here; the desktop rule is untouched.
- **Clicking a body pauses the simulation, deliberately — but only for
  planets.** Opening a publication should give the best picture of its object:
  `heroPose` puts the camera on the Sun's side so the lit face is toward you
  and centres it, and a stationary body is the rest of that. Press play and
  everything resumes, with `followTick` riding the object as it moves.

  This has flipped twice, so know why it sits where it does. The pause lives
  in `camera.js`'s `zoomToBody` wrapper ONLY. `app.js`'s copy in `showDetail`
  stays removed. The difference is VIPER: `pausedPlanets` also gates
  `MoonMission.stepRover`, so pausing kills the drive arrows outright — and
  `camera.js` returns early for Moon and VIPER two lines above the pause,
  while `showDetail` has no such early return and runs for VIPER too.

  **Do not "simplify" this by moving the pause back to one place.** The split
  is the whole point.

### Traps that cost real time this session

1. **`timeout` does not exist on macOS.** Use `perl -e 'alarm shift; exec @ARGV'`.
   A command using `timeout` fails with "command not found" before Chrome ever
   starts, and produces a zero-byte output that looks like a Chrome failure.
   This was misdiagnosed three times as "the environment has degraded".
2. **`--screenshot` and `--dump-dom` in the same invocation produce NEITHER.**
   Use one per run.
3. **The disk fills, and it kills git.** The user's data volume runs at 95–100%.
   A headless Chrome profile on a WebGL page can consume 400 MB+ **while
   running**, before any cleanup line executes. At 0 bytes the Bash tool cannot
   create its own output file and *every* command fails. Always pass the cache
   flags above, always `rm -rf` the profile, and check `df -h /` before
   launching. An orphaned headless Chrome once filled the disk on its own —
   `pkill -9 -f 'Chrome --headless'` reclaimed 1 GB instantly.
4. **A screenshot is a crop, not a scaled render.** Headless laid out at 500 CSS
   px while capturing a 390 px window, so the right edge was simply missing from
   the image. This was misdiagnosed as a horizontal-overflow bug, twice. Before
   claiming overflow, measure: `document.documentElement.scrollWidth` vs
   `clientWidth`, and walk elements comparing `getBoundingClientRect().right`.
5. **`--virtual-time-budget` freezes CSS transitions.** `getComputedStyle` keeps
   returning the transition's *start* value forever. Set
   `el.style.transition = 'none'` in the probe before measuring anything animated.
6. **rAF barely ticks under virtual time.** Verify the *pose* the camera will
   settle on, not the pixels. Use `setTimeout`, which virtual time fast-forwards.
7. **`.click()` is not a click** — skips hit-testing. Use `elementFromPoint`.
8. **A commit message with double quotes breaks `git commit -m` in this shell.**
   Write the message to a file and use `git commit -F`.
9. **MutationObserver loops freeze the page silently and totally.** See §7.

## 7. The freeze, in full, because it will teach you the codebase

The user reported: "click Earth and the whole app freezes, publication never
appears". Two separate causes, both introduced during the same session:

**Cause 1 — infinite MutationObserver loop (`demo/pub-swipe.js`).**
The file observed `#detailView` with `{childList: true, subtree: true}`, and its
`sync()` wrote `textContent` into the `‹ n of m ›` nav — which lives in
`.detail-header`, **inside `#detailView`**. Every write fired the observer that
had just called `sync()`, which wrote again. MutationObserver callbacks are
microtasks, so this starved the event loop and hard-froze the tab. It fired
whenever `showDetail` mutated the detail view — every click on every body.

Fixed two ways, because the failure is silent and total: the observers now watch
only the `class` attribute and `#detailTitle` (which sits in `.detail-content`,
a sibling of the header, so nothing `sync()` writes is visible to them), and the
writes are idempotent. **Assigning the same string to `textContent` still
replaces the node and still counts as a mutation** — idempotence has to be
explicit.

**Cause 2 — `camera.js` paused the simulation on every body click.**
`demo/camera.js`'s `zoomToBody` wrapper set `pausedPlanets = true` to "hold the
scene still on the hero view". From the visitor's side that is a page that has
stopped responding. Removed. `followTick` (`camera.js:111`) re-reads the
followed body's world position every frame and rides it, so the hero view
tracks a moving planet by design.

**Note `zoomToBody` is called twice per planet click** — once at `app.js:2450`,
again 300 ms later inside `showDetail`. The second flight cancels the first via
the `follow !== leg` guard, so it is survivable, but it is a wasted flight and a
plausible source of stutter. Not fixed.
