## Decisions already made, and why

- **The tour never auto-starts.** Recorded in `demo/tour3.js` at the bottom: "Never
  auto-start, on any device... arriving visitors were getting it before they had
  looked at anything." It was tried and reverted. Do not re-enable it.
- **Four tour modes exist** behind `?tour=guided|hotspots|cinematic|practice`,
  default `guided`. If Option A stalls, `hotspots` is self-paced and moves nothing
  on its own, which may sidestep the lag entirely. It has never been judged.
- **Desktop must not change** unless explicitly asked. This is a standing rule from
  the user and was broken twice in the last session, both times reverted. Mobile
  work goes behind the `.mobile-device` class that the inline script in `<head>`
  sets before first paint.
- **Planet textures**: Moon, Mercury and Mars keep their 2048px files because the
  shader derives crater relief from their luminance (`BUMP` at
  `js/planets-real.js:136`). The other nine ship 1024px copies to phones only,
  chosen through `texUrl()` in the same file. Do not "simplify" that away.
- **No em-dashes in user-facing content.** A previous session removed 25 of them on
  request. Use commas or middots.

## Traps

These each cost real time. Read them.

- **Headless Chrome with `--virtual-time-budget` starves `requestAnimationFrame`.**
  Camera flights, the render loop and anything driven by rAF effectively do not
  run. Verify target state (`__cam.following`, class names, DOM) rather than pixels
  or positions. Several checks last session were reported as "reasoned, not
  measured" for exactly this reason, and that is the honest thing to do.
- **Timings from swiftshader are meaningless in absolute terms.** The same
  unchanged page measured 104,697 ms in one run and 24,000 ms in another. Only
  compare within a single run, and alternate A/B if you must compare at all.
- **`renderer`, `camera`, `bodies`, `scene` are top-level `const` in `js/app.js`.**
  They live in the global lexical scope and are NOT on `window`. From a probe you
  must reach them with `frame.contentWindow.eval('...')`. `w.renderer` is
  `undefined` and will throw.
- **Cutting bytes did not make the page feel faster.** Mobile went from 6259 KB to
  3608 KB (42%) across several commits and the user reported no difference. Do not
  spend time there again without evidence that the network is the constraint.
- **ResearchGate returns 403 to `curl` for every URL**, including public ones, so
  curl cannot tell you whether a page is publicly viewable.
- **Local server**: `python3 -m http.server 4321 --directory <repo>`. It gets
  killed by background time limits; just restart it.

  `/Users/gbdf/Documents/Workspace/Portfolio/space-mobile/interactive-space-portfolio`
  pointing at `interactive-space-portfolio-2.git`. That is NOT the deployed site.
